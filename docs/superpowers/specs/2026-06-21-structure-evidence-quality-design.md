# Word2JATS 结构证据驱动质量优化设计

## 目标

在不依赖样例文件名、不调用外部 API、保持现有接口兼容的前提下，继续提升图表、公式和正文交叉引用的真实结构质量。系统采用保守识别策略：确定性结构自动输出，模糊结构保留原文并标记人工复核，JATS Publishing 1.3 DTD 通过率保持 100%。

## 当前基线

- 官方样例数量：5 篇
- 平均语义相似度：91.4%
- 最低单篇相似度：88%
- JATS Publishing 1.3 MathML3 DTD 通过率：100%
- 已知短板集中在多面板图片、图片化表格、复杂公式表达、英文单词编号表引用、复合参考文献引用和对象归属解释性。

## 总体架构

保留 `DocumentFlowParser -> DocxParser -> JatsGenerator -> Validator` 主流程，在解析与生成之间引入轻量结构证据层：

1. `DocumentFlowParser` 输出真实顺序、节点类型、样式、编号、对齐、媒体关系和 OMML 特征。
2. `DocxParser` 收集候选图表、题注、公式、章节和引用关系。
3. 新增 `StructureEvidence` 服务，对候选关系计算置信度、状态、判定证据和问题。
4. `JatsGenerator` 仅对目标存在且达到阈值的关系生成正式 JATS 结构。
5. `QualityScorer`、文档流视图和图表预览展示判定依据与修复建议。

该层只消费已有数据，不重新解析 DOCX，也不替代业务对象模型。

## 统一证据结构

图、表、公式和引用对象可选增加：

```json
{
  "confidence": 0.86,
  "status": "ok",
  "evidence": ["题注编号一致", "位于同一章节", "距离媒体 1 个节点"],
  "issues": []
}
```

状态与阈值：

- `confidence >= 0.80`：`ok`，自动进入正式 JATS XML。
- `0.50 <= confidence < 0.80`：`need_review`，允许保留结构但必须进入质量报告。
- `confidence < 0.50`：`warning`，不强行建立关系，保留原始节点与候选信息。
- 确定性错误（目标不存在、跨章节误绑、媒体路径无效）：`error`。

阈值由服务常量统一管理，不在解析器各处分散硬编码。

## 图表判定

### 图片与图题

证据权重依次为：显式编号一致、同一章节、文档距离、题注方向、连续媒体、多面板标记。禁止跨章节自动绑定。

- 单图题绑定最近的同章节未绑定图片。
- 明确出现 `(A-B)`、`panels`、`plots` 等多面板证据时，可将连续图片归入一个 `fig` 并输出多个 `graphic`。
- 仅凭多个连续图片不得自动合并。
- 多余图片保留为无题注 figure，状态为 `need_review`。
- 多余图题保留为 caption-only figure，状态为 `need_review`。

### 表格与表题

- Word 原生表格、图片化表格分别记录 `rows` 或媒体路径。
- 显式表题与后继表格/图片优先绑定；同章节内可使用最近邻补充。
- 复杂文本排版表格不强行重建单元格，保留为 `need_review` 候选，避免将数据行误判为章节。
- 行列统计、空题注、空数据和引用完整性进入质量报告。

## 公式判定

- `m:oMathPara`、纯 OMML 段落、居中或右对齐且带公式编号的段落判定为独立公式。
- 与自然语言同段的 OMML 保留行内语义，不生成额外 `disp-formula`。
- 规则公式必须同时满足短文本和明确运算结构，单独希腊字母或缩写不构成公式。
- OMML 转换继续采用 `success/partial/failed`；`partial` 输出可用 MathML/LaTeX 并标记复核，`failed` 保留原始 OMML 和文本。
- 多个公式只按文档流节点定位，不根据全局序号重新排序。

## 交叉引用判定

- 支持图、表、公式和参考文献的单个、并列、范围引用。
- 支持阿拉伯数字、中文标记和英文单词表编号（one 至 twenty）。
- 统一使用目标对象的实际 ID 建立 `rid`，不凭文本生成不存在的目标。
- 生成阶段保留原始引用文字；Schema 自动修复可移除无效 `rid`，但不得删除正文文字。
- 复合 `rid` 按目标拆分参与评测和引用完整性统计。

## 质量报告联动

`QualityScorer` 增加或细化：

- 图题/表题绑定置信度与跨章节检查。
- 公式成功、部分成功、失败数量和不支持特性。
- xref 已解析、部分解析、未解析和无效目标数量。
- 每个问题包含 `level`、`module`、`location`、`message`、`suggestion` 和 `evidence`。

前端沿用现有质量报告、文档流对照和图表预览，不增加新的编辑器。

## 错误处理

- 单个节点解析或证据计算失败不得终止整篇转换。
- 失败对象使用 `need_review` 或 `error`，并保留原文、媒体路径、OMML 或候选目标。
- 自动修复仅处理可证明正确的节点顺序、命名空间、重复 ID 和无效 IDREF。
- 出版方补录的 DOI、期刊 ID、ISSN、ORCID 不计为源文档解析错误。

## 测试与验收

### 单元与集成测试

- 高置信度图题/表题绑定。
- 跨章节候选拒绝绑定。
- 明确多面板合并与普通连续图片不合并。
- 图片化表格与 Word 原生表格。
- 行内 OMML 与独立 OMML 区分。
- Unicode 范围、并列、英文单词编号 xref。
- 目标缺失时保留正文并通过自动修复获得合法 DTD。
- `need_review` 对象进入质量报告。

### 回归门槛

- 后端完整 pytest 全部通过。
- 前端 `npm run build` 通过。
- 五篇官方样例 JATS 1.3 DTD 通过率保持 100%。
- 平均语义相似度不得低于 91.4%，最低单篇不得低于 88%。
- 图表、公式、xref 三个分项中至少两项获得可量化提升；若分数未提升，必须由新增定位准确率或误判减少的测试证据证明质量改进。

## 非目标

- 不针对样例文件名或文章主题硬编码。
- 不追求与出版方人工润色文本逐字一致。
- 不实现图片公式 OCR、完整 Office Math 覆盖或复杂文本表格视觉重建。
- 不改变 `/api/convert`、`/api/generate-xml`、批量转换和 ZIP 导出的请求结构。
